## REQ-001：通用窗口框选识别与回复建议

更新日期：2026-10-08。用户明确不限定 Soul、聊天软件或模拟器品牌，并在后续同意全部推荐方案、授权开发。已在本地源码实现，使用说明与实际限制见 SCREENSHOT-ASSISTANT.md；以下保留需求设计依据。

### 已确认的需求

用户选择任意可正常截图的窗口，圈定聊天区域，软件识别文字并生成回复建议；最终由用户人工输入和发送。支持保存和复用我的资料及对象档案。

不以模拟器品牌或聊天应用白名单作为使用前提。Soul、模拟器、桌面聊天客户端和浏览器聊天页面均可作为使用场景；这不代表保证所有窗口都能正常截图或所有布局都能准确识别。

### 第一版流程（交互细节待确认）

1. 用户打开目标窗口，手动选择窗口并框选聊天区域。
2. 点击按钮或快捷键采集一次当前可见内容，本地 OCR 提取文字。
3. 展示识别文字、顺序和双方归属，允许用户修正或删除无关内容；无法可靠区分说话人时提供人工标注，不静默认定。
4. 选择当前会话及对象档案，或新建档案；已有资料自动回填。普通回复不强制建档。
5. 用户点击生成，将检查后的聊天及本次确认的必要资料发送给已配置模型，展示候选回复。
6. 用户自行在原聊天软件输入并发送。
7. 用户可以在生成前或生成后保存、修改对象资料。保存不依赖生成成功，也不请求模型。
8. 切换对象时手动切换或新建会话，核对档案，隔离不同对象的上下文。

### 识别与窗口范围

- 第一版聚焦单聊文字，只读取所选区域当前可见内容，不自动翻页获取历史。
- 框选代替针对某款软件硬编码消息区；不能只依赖微信气泡颜色或特定模拟器布局判断消息。
- 尽量排除工具栏、时间提示等非消息文字，并保留人工校正入口。
- 同一窗口可以切换不同聊天，窗口标题、进程名或句柄不等于对象身份。
- 窗口尺寸、缩放或布局改变后，建议提示重新核对区域；具体跟随和校准方式待确认。
- 黑屏、空白、窗口关闭或截图失败时提示异常，不继续生成；具体检测能力需实测。
- 不读取聊天数据库，不使用模拟器内部控制或自动登录接口。

### 资料保存与军师模式

- 复用 REQ-002 已完成的“我的资料＋多个对象档案”、本地加密保存及修改／删除能力，不按应用另建重复人设。
- “保存资料”延续现有人设功能：保存用户主动填写、检查的背景、关系、共同经历、目标与边界；不默认长期保存全部聊天、截图或生成结果。
- 资料可以在生成前后保存；不自动把 OCR 内容或模型推测写入人物事实。
- 同一对象跨应用复用档案由用户明确选择；同名对象不自动合并。
- 显示“当前会话 → 使用档案”；可以带出手动关联的候选，但不能仅凭窗口标题或 OCR 昵称静默确认身份。
- 可选军师模式；保存、加载或关联档案不自动启用后台分析。
- 切换对象、选择其他档案或修改资料后，已有建议需标为旧结果；延迟请求结果不能覆盖新会话或新资料版本的结果。
- 现有档案模块已与通用框选流程衔接；保存和使用档案均不触发模型请求。

### 模型用量控制

- 截图、本地 OCR、检查文字及保存／加载档案不调用模型。
- 建议只在用户点击生成或重新生成时请求模型；采集、窗口变化、新消息均不自动生成。
- 不能直接沿用现有桌面军师随新消息持续分析的触发方式。
- 只发送必要的最近聊天，允许生成前删减；条数和长度上限待确认。
- 优先使用本地 OCR，不因支持任意窗口就默认新增视觉模型调用。
- 一个模型配置不等于一次请求；分析、起草、排序可能分别请求。费用取决于上下文长度、启用步骤和生成次数，不承诺固定费用。

### 暂不纳入第一版

- 自动填入、粘贴、模拟键盘输入或发送回复。
- 持续自动采集、自动切换对象或翻页抓取历史。
- 语音、视频、图片和表情包的语义理解；截图中的可见文字仍属于 OCR 范围。
- 自动长期保存全部聊天、自动保存未经用户核对的人物推测。
- 绕过目标应用截图限制，或保证所有布局／主题都能无误识别。

### 验收条件（开发前细化）

- 窗口选择不按应用品牌排除目标；用不同来源的虚构聊天画面验证，不只测 Soul。
- 能获取用户所选区域，展示可检查、可修正的文字、顺序和双方归属。
- 无法可靠识别时允许修正或重新采集，不将不确定归属当作确认事实。
- 未明确点击生成时没有模型请求；请求只包含当前检查后的聊天及确认的资料，不带其他对象档案。
- 采集、生成、保存均不向目标聊天软件写入或发送内容。
- 保存过的资料重启后可选择回填；模型未配置或生成失败时也可独立保存用户填写的资料。
- 切换会话或修改资料后，旧请求不覆盖当前结果，也不被误标为基于新资料生成。
- 默认不将截图、聊天、真实档案或密钥写入调试日志及发布文件。

### 已确认方案与技术验证记录

- 独立截图助手窗口，保留原有微信流程；打开助手时暂停自动采集，关闭后不自动恢复。
- 默认 Ctrl + Alt + K 单次识别，允许选择其他字母；保留 J 给原采集开关。
- 本次运行记住窗口区域；窗口移动时坐标随目标窗口，大小／DPI 变化在下一次采集时要求重新框选。布局变化仍由用户检查。
- 说话人提供左右位置建议，可手动标注和修改；允许移动、合并、删减文字。
- 默认最近 10 条，可选 3～30 条；复用三条候选生成流程，军师默认关闭。
- 手动命名和切换会话，各自保留进程内上下文；只长期保存主动填写的档案。
- 使用自建虚构窗口完成真实 WGC 截图与 OCR 验证，未采集真实聊天。不同实际应用仍需逐一验证兼容性，不限定品牌。

### 现有能力与缺口

本地源码新增任意可见目标窗口选择、快照框选、单次 OCR、识别结果编辑及手动会话流程，复用原模型与档案功能；没有沿用微信专属消息区识别。通用截图并不保证全部聊天布局均能准确识别，需要用户核对。

## REQ-002：军师模式资料保存与自动填入

记录日期：2026-10-08。最初仅记录；随后用户同意推荐方案并授权开发。当前已在本地源码实现，使用说明见 ADVISOR-PROFILES.md。以下保留需求与方案记录。

### 用户需求与现状

进入军师模式时，不再反复填写固定的人设和背景信息。资料填写并保存一次后，可在再次打开、切换会话及重启软件后复用，需要时再修改。

当前军师窗口包含“当前关系、当前目标、确认过的背景、边界”四项。资料仅存于进程内存；切换会话后取消确认，再次打开时可能不回填，退出后不保留。现有设置中的“说话风格”已经能保存，应复用而非另建一份相互冲突的设置。

### 已认可的方案方向

| 资料类型 | 内容 | 使用方式 |
| --- | --- | --- |
| 我的资料 | 用户主动填写的基本背景、说话习惯、表达偏好与边界 | 一份共用资料，填写一次，可随时修改；说话风格复用现有设置 |
| 对象档案 | 对方已知背景、当前关系、重要经历、沟通边界 | 多个对象分别保存，选择档案后自动填入 |
| 本次目标 | 自然接话、邀约、修复、拒绝等 | 可记住上次选择，每次允许调整，避免长期固定为过期目标 |

不新增整套必填问卷，不知道的信息可以留空；不将猜测作为已确认的人物事实保存。

### 建议交互与保存规则

- 军师窗口增加对象档案选择，以及新建、保存修改、删除入口。
- 选中档案后回填相关字段；已保存的内容在关闭窗口、切换会话和重启后仍然存在。
- “保存资料”与“启用并生成”分开。保存、加载、编辑档案本身不调用模型；未保存编辑如何提示或放弃，开发前确定。
- “停用军师”保留已保存资料；“删除档案”才永久移除相应档案及关联，避免误清空。
- 识别到已关联聊天时，可以自动带出候选档案，明确显示“当前聊天 → 使用档案”，经用户确认后才用于生成。
- 当前聊天标题来自 OCR，没有可靠的账号唯一标识。不能仅凭同名标题静默认定是同一对象；识别不确定、改名或存在多个候选时，应允许用户手动选择。
- 切换对象时取消旧对象的使用确认，旧请求的延迟结果不得显示在新对象下。是否对同一会话重复打开沿用确认状态，开发前确定。
- 后续 REQ-001 接入通用窗口框选时，可手动选择已有对象档案；跨平台关联由用户明确指定，不自动合并同名对象。

### 本地数据与模型用量

- 建议保存到 Windows 当前用户的应用数据目录，与源码、安装包分开；发布构建必须排除实际用户档案。
- 第一版只保存用户主动填写并保存的资料，不自动保存全部聊天，不让模型自行改写档案。
- 只向模型提供本次所需的我的资料、当前选中对象资料和本次目标，不发送其他对象档案。
- 保存和回填不增加模型调用次数；生成时提交的资料越长，输入 token 可能越多，因此应控制字段长度和重复内容。
- 本地存储方式、是否加密、备份及卸载时保留或删除资料的行为待确认；不将普通本地文件描述为加密保险库。

### 验收条件（开发时落实）

- 保存资料后关闭并重启，内容仍能正确加载，不要求重复填写。
- 不同对象的资料相互隔离，修改或删除一个对象不影响其他对象。
- 公共说话风格只有一处有效来源，不与档案字段冲突。
- 自动回填与模型请求分离；仅选择或保存档案不会产生 API 请求。
- 发起生成时使用用户当前确认的资料和目标，不混入其他对象背景。
- 停用军师后资料仍保留；删除后的档案不再被自动回填。
- 文件损坏或写入失败时明确提示，不将保存失败显示为成功，也不静默覆盖可用档案。
- 源码、安装包、调试日志中不包含实际用户的人设、对象资料或密钥。

### 待确认事项

- 我的资料具体字段，以及原有“背景／边界”如何拆分为公共资料和对象专属资料。
- 档案命名、聊天关联和同名冲突的界面细节。
- 默认目标是否按对象记忆，以及未保存编辑的处理方式。
- 本地存储保护、备份与卸载数据处理方式。
